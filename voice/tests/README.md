# voice/tests

Two tiers:

1. **`pytest` suite** (`test_context_loader.py`) — unit tests for the
   loader. Network-free. Run with `uv run pytest tests/`.
2. **Live smoke/eval scripts** (`live_smoke.py`, `bridge_smoke.py`,
   `audio_relay_smoke.py`, `resumption_smoke.py`, `brock_eval.py`,
   `brock_eval_single.py`) — exercise the bridge and Gemini 3.1 Flash
   Live. Require `GOOGLE_API_KEY` and burn real quota. Not part of
   pytest — invoke explicitly.

## Ordering

Run top-to-bottom when validating the whole stack:

```bash
uv run pytest tests/                                # unit tests
uv run python tests/live_smoke.py                   # raw SDK auth check
uv run python tests/bridge_smoke.py AUDIO           # bridge in AUDIO mode
uv run python tests/audio_relay_smoke.py            # mic PCM → bridge → audio out
uv run python tests/resumption_smoke.py             # handle round-trip
uv run python tests/brock_eval_single.py            # Day 3 eval gate
```

## Brock eval setup

`brock_eval.py` and `brock_eval_single.py` target `document_id =
brock_april_13_2026`. `context_loader` looks for two files in
`examples/`:

| path                                     | source                                 |
| ---------------------------------------- | -------------------------------------- |
| `brock_april_13_2026.pdf`                | tracked, shipped with the repo         |
| `brock_april_13_2026_output.md`          | generated by Agent A (gitignored)      |

Until Agent A's output lands, symlink the hand pre-read as a stand-in:

```bash
ln -sf brock_april_13_2026_prereadhand.md \
    examples/brock_april_13_2026_output.md
```

Once Agent A ships, the symlink can be removed and the real generated
pre-read will be picked up automatically.

## `brock_eval.py` vs `brock_eval_single.py`

- `brock_eval_single.py` — **the Day 3 gate.** Opens one session, seeds
  context once, asks all five questions on it. Mirrors the demo UX.
- `brock_eval.py` — older variant that opens a fresh session per
  question. Retained for cold-start quality checks. Each question gets
  its own 60k-token seed, which is ~5× the quota cost of the single
  variant.

Both write a markdown report next to the script (`brock_eval_output.md`
and `brock_eval_single_output.md`), and both tee the bridge's log to
`.gitignore`'d `*_bridge.log` files for post-run debugging.

## Notes on 3.1 Flash Live

- Audio-first. TEXT modality returns `1011 Internal error`. Always pass
  `modality: "AUDIO"` in the init message. Read replies off
  `transcript` frames (accessibility + observability) plus the binary
  PCM stream (24 kHz 16-bit LE mono).
- Responses are elicited via `send_realtime_input(text=…)` from the
  bridge side. `send_client_content(turn_complete=True)` does not
  trigger a reply on this model variant — it is used only for seeding
  with `turn_complete=False`.
- `session.receive()` is one iterator **per turn**, not per session.
  The bridge wraps it in a `while True` to stream many turns over one
  WebSocket; make sure any SDK-direct test does the same.
